# SlotLedger — Project Log

## 1. Project goals

SlotLedger is an educational TypeScript application for booking rooms.

Main goals:
- Build a public GitHub portfolio demonstrating practical TypeScript skills.
- Learn how to implement and test business rules.
- Develop automated tests using Vitest and Playwright.
- Create a realistic demo application for the QA Release Check service.
- Eventually prepare a sample QA report based on testing this application.

The project is developed incrementally alongside the owner's full-time QA job.

### TASK 002 — Booking time validation

Status: Completed and committed

Commit:
`e1f0042` — feat: complete booking time validation

File:
- `src/validation/bookingValidator.ts`

Function:
- `timeValidation(startTime: string, endTime: string): boolean`

Requirements:
- Accept time strings in the `HH:mm` format.
- Accept hours from 00 to 23 and minutes from 00 to 59.
- Return `true` only when the end time is later than the start time on the same day.
- Reject equal times, earlier end times and bookings crossing midnight.

Completed:
- Implemented comparison by converting hours and minutes into minutes since midnight.
- Added input-format and time-range validation.
- Removed temporary debugging checks.

Verification:
- Production build passed.
- Automated unit tests were subsequently added and verified in TASK 003.
- The correct strict comparison (`<`) was restored after the TASK 003 negative check.

### TASK 004B — Room existence validation

Despite its title, this commit includes `roomExists()` and its three unit tests.

Completed:
- Added `roomExists(roomId: number, rooms: Room[]): boolean`.
- Uses `Array.some()` to check whether a room with the requested ID exists.

Learning notes:

### TASK 004C — Booking overlap detection

Status: Implementation and tests completed (2026-10-04); final commit status should be verified in Git

Function:

`roomOverlap(startTime: string, endTime: string, roomId: number, bookings: Booking[], date: string): boolean`

Completed:
- Checks only bookings for the same room and date.
- Detects partial overlaps.
- Detects full containment in both directions.
- Detects identical ranges.
- Allows bookings that only touch at a boundary.
- Returns `false` for an empty booking list.
- Assumes time ranges have already passed `timeValidation()`.
- Added 11 overlap tests.

Test coverage includes:
- partial overlap,
- existing booking containing the new booking,
- new booking containing the existing booking,
- both touching-boundary directions,
- different dates,
- different rooms,
- empty list,
- identical ranges,
- collision only in the second list item,
- ranges fully before and fully after an existing booking.

Verification:
- 33/33 total Vitest tests passed.
- TypeScript/Vite production build passed.

Independent review (2026-10-05):
- Reviewed `bookingValidator.ts` and `bookingValidator.test.ts`.
- No blocking correctness issue was found in the current TASK 004 implementation.
- `roomOverlap()` correctly uses the rule that a collision exists only when the same room/date applies and the ranges are not separated by or merely touching a boundary.
- Direct string comparison is acceptable here because the function explicitly assumes validated, fixed-width `HH:mm` values.
- Keeping `timeValidation()`, `canCreateBooking()`, `roomExists()` and `roomOverlap()` as separate rules is appropriate for the current learning/portfolio scope.
